# FAQ

## Это бот Telegram?

Нет. Основной процесс входит как пользователь. Companion-бот нужен только для Control Center.

## Почему Haruka называется движком?

Потому что её главный продукт — lifecycle, SDK, диспетчер, хранилище, безопасность и UI управления. Команды можно добавлять независимо как расширения.

## Можно ли ставить Hikka-модули?

Часть простых модулей работает через адаптер. Полной совместимости нет: глубокие внутренние API, сложные inline units и специфичные monkey patches нужно портировать.

## Где хранятся данные?

По умолчанию в `~/.haruka`: SQLite, Telegram-сессия и каталог модулей. Путь меняется через `HARUKA_DATA_DIR`.

## Безопасно ли загружать любой модуль?

Нет. Модуль — исполняемый Python-код внутри процесса. Он потенциально может читать сессию, файлы и отправлять данные.

## Почему Control Center требует отдельного бота?

Inline-клавиатуры и callback query принадлежат bot API. Companion-бот даёт интерактивное меню, а пользовательская сессия остаётся командным транспортом.

## Haruka уже лучше Heroku?

Не во всём. У Haruka чище новая архитектура и сильнее акцент на engine contracts. У Heroku значительно зрелее экосистема, совместимость, onboarding и количество проверенных функций. Подробное сравнение — в [отдельном документе](HARUKA_VS_HEROKU_RU.md).
